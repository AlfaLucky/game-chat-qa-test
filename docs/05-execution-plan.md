# 05. План выполнения и отчётности

## Порядок проверки

1. **Контракт и окружение.** Уточнить спецификацию, заведённые аккаунты/права, доступ к серверным событиям и клиентским логам.
2. **Smoke.** Открыть чат, переключить канал, отправить текст, получить его другим игроком, проверить отсутствие доступа для неучастника.
3. **Core functional.** Ввод, границы, история, счетчики и состояния интерфейса.
4. **Reliability.** Потеря сети на трёх участках: до запроса, после серверного commit и после ответа; reconnect и быстрые повторы.
5. **Authorization/security.** Членство в канале, смена пользователя, прямой API-доступ к чужому conversation ID.
6. **Game integration.** Одноразовое серверное действие, повторение, гонки и сверка игрового состояния.
7. **Compatibility/performance.** Поддерживаемые платформы, локали, длинные истории, клавиатуры, переходы foreground/background.
8. **Regression / release review.** Повторные P0/P1, проверка фиксов, анализ оставшихся рисков.

## Шаблон баг-репорта

- **Заголовок:** [Chat][Android/iOS][Module] краткое нарушение инварианта
- **Build / OS / device / account:** версия, устройство, роль игрока
- **Preconditions:** серверные данные, membership, flags
- **Steps:** минимальная последовательность, сетевые условия
- **Actual / Expected:** наблюдаемое нарушение и целевое поведение
- **Evidence:** video/screenshot, timestamp UTC, request_id/message_id, client & server logs (без персонального контента)
- **Reproduction:** x/y попыток
- **Impact / Severity / Priority:** раздельные обоснования

## Результаты проверки

В этом кейсе **нет** реального тестового окружения и фактических результатов прогонов. Статусы Pass/Fail/Blocked не проставлены намеренно. Для реального запуска создаётся отдельный execution log с билдом и временной меткой.

# 04. Риски и вопросы к требованиям

## Реестр рисков

| ID | Риск | Последствие | Способ обнаружения | Приоритет |
|---|---|---|---|---|
| R-01 | Повторная игровая операция при double tap/retry | двойная выдача ресурса или нарушение экономики | два параллельных запроса с одним action ID, сравнение server ledger | P0 |
| R-02 | IDOR в приватном диалоге | чтение/отправка чужих сообщений | подмена conversation_id, membership/token | P0 |
| R-03 | Потеря ack после принятия сервером | потеря или дублирование сообщения | disconnect между commit и ответом, повтор request ID | P0 |
| R-04 | Утечка кеша между аккаунтами | раскрытие переписки предыдущего игрока | logout → login нового аккаунта без перезапуска и после него | P0 |
| R-05 | Reconnect даёт пропуски событий | потеря части истории | сверка server sequence/cursor при offline → online | P1 |
| R-06 | Гонка при чтении/непрочитанных | неверные бейджи и положение курсора | 2 устройства, параллельное открытие каналов | P1 |
| R-07 | Неэкранированный контент | XSS/поломка рендера или вредоносная ссылка | опасные строки, URL, управляющие символы | P1 |
| R-08 | Нагрузочная деградация длинной истории | лаги, рост памяти, блокировка ввода | крупные треды, прокрутка и отправка одновременно | P2 |

Риски сформулированы для вымышленной системы. Уровень определяется потенциальным ущербом, а не вероятностью ошибки в существующем продукте.

## Open questions — Product Owner

1. Какие типы каналов существуют? Кто может их создавать и закрывать?
2. Что означает `online` — открытая игра, активный чат или присутствие в выбранном канале?
3. Можно ли писать пользователю вне списка друзей/группы?
4. Есть ли лимит длины сообщения, количество отправок в минуту и антиспам?
5. Есть ли возможность редактировать, удалять, блокировать или жаловаться?
6. Каковы правила хранения истории и удаления данных аккаунта?
7. Какие типы системных карточек поддерживаются? Какие действия одноразовые?
8. Есть ли поведение unread при нескольких устройствах одного игрока?
9. Как клиент должен вести себя при неотправленном черновике и выходе из канала?
10. Требуются ли ограничения по возрасту, региону или модерации контента?

## Open questions — Backend

11. Есть ли `client_request_id`, серверный `message_id` и контракт идемпотентности?
12. Какой серверный порядок гарантируется: монотонный sequence per channel или timestamp?
13. Какой механизм восстановления пропусков и пагинации истории?
14. Как обрабатываются таймаут после commit и повторные запросы?
15. Как проверяется членство/авторизация на чтение и отправку?
16. Как изолируется кеш/история между аккаунтами?
17. Какой API возвращает проверяемый результат игровой операции?
18. Какие данные разрешено записывать в логи и аналитику?

## Open questions — Client / UX

19. Есть ли статусы sending/failed/sent, можно ли вручную повторить отправку?
20. Как работают клавиатура, автоскролл, фон и возвращение в приложение?
21. Как выглядят пустой канал, запрет на отправку, истёкшая сессия и no network?
22. Какие версии iOS/Android, минимальные экраны, font scale и RTL поддерживаются?

## Что необходимо согласовать перед выполнением

API contract, тестовые роли, feature flags, макеты реальных ошибок, правила ретенции, перечень системных карточек и наблюдаемую серверную телеметрию.

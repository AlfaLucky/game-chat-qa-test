# Game Chat · QA Case Study

**Автор:** Andrey Shiryavsky · Game / Mobile / Client–Server QA  
**Формат:** независимый демонстрационный кейс по проектированию тестирования.

> Это самостоятельная учебно-портфолио модель вымышленной игровой системы. Здесь нет исходного макета, данных, названия, текстов или иных внутренних материалов работодателя. Проверки спроектированы на основе допущений и **не выполнялись на реальном билде**.

## Задача

Показать подход к проверке игровой системы сообщений: не только отправку и отображение текста, но и модель состояний, права доступа, сетевую устойчивость, синхронизацию нескольких клиентов и интеграцию действий чата с серверным игровым состоянием.

**Модель продукта:** вымышленная мобильная игра *Arcadia*. Каналы: глобальный, группа и личный диалог. Текстовые сообщения доставляются через клиент-серверную систему. Специальные карточки могут запускать игровое действие. Вся модель — допущение для проектирования, а не подтверждённая спецификация реального продукта.

## Приоритеты

- **P0** — утечка приватных данных, необратимая потеря сообщения или повторное изменение игрового баланса.
- **P1** — основной поток и целостность данных при типичных сбоях.
- **P2** — удобство, нестандартные входные данные, нефункциональные свойства без критического эффекта.

Приоритет — предлагаемый до согласования с владельцем продукта; он не равен тяжести уже найденного дефекта.

## Принципы

1. Разделять наблюдаемое поведение, допущение и открытый вопрос.
2. Проверять последствия на сервере, если UI может скрывать ошибку.
3. Проектировать сценарии для гонок, повторов и восстановления, а не только happy path.
4. Не публиковать фиктивные результаты выполнения, показатели производительности или выдуманные баги.
5. Сохранять воспроизводимость: конфигурация, тестовые игроки, сетевые условия, идентификаторы запросов и логов.
